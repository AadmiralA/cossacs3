## Что искать в логе

| Маркер | Что можно проверить |
|---|---|
| `NavalRamming ACCEL_START/50/75/FULL_SPEED` | Разгон корабля и фактическое игровое время |
| `OVDIAG CONFIG` | Инициализация характеристик: HP, урон, пауза, выключенный мортирный слот галеры, содержание золотом в конфиге |
| `OVDIAG MORTAR_MEMBER_DISABLED` | Удаление мортиры из списка страны (НЕ полное удаление ассетов) |
| `OVDIAG GUN_INIT` | Замедленная величина шага у пушки и гаубицы |
| `OVDIAG CAV_INIT` | Инициализация конного юнита |
| `OVDIAG CAV_STATE` | Реальное построение, движение, базовый разгон, множитель натиска |
| `OVDIAG CAV_BLOCK reason=NO_FORMATION` | Отсутствие действующего построения |
| `OVDIAG CAV_ENEMY` / `CAV_CONTACT` | Наличие вражеской цели, угол и дистанция |
| `OVDIAG CAV_BLOCK reason=PIKES` | Блокировка натиска пикинёрами (на уровне юнита, не всего фронта) |
| `OVDIAG CAV_BOOST_START/MAX/END` | Плавное достижение ускорения ×2,5 тяжёлой конницы |
| `OVDIAG CAV_HIT_CHECK` / `CavalryCharge HIT` | Базовый урон и условия натиска |
| `OVDIAG DAMAGE_GLOBAL` | Множитель урона мобильного юнита ×0,625 до брони |
| `OVDIAG HP_APPLY` | **Ключевое:** итоговый HP до/после, базовый и реальный урон после защиты |
| `OVDIAG RELOAD` | Фактическая пауза атаки и наличие построения |
| `OVDIAG AI_ORDER` | Приказ ИИ произвести орудия |
| `OVDIAG AI_ART_LIMIT` | Отказ ИИ производить артиллерию сверх лимита 10 |

**Нет записи ≠ механика сломана:** конкретное условие могло не возникнуть. Например, `AI_ART_LIMIT` не появится, пока ИИ не достигнет лимита.

Некоторые проверки статические: `CONFIG` доказывает установленное значение, но не поведение в бою; `GUN_INIT` доказывает установку шага, но не реальную траекторию. Само событие `CavalryCharge HIT` доказывает только вызов атаки; ищи `HP_APPLY` для изменения здоровья.

## Минимальный тест одной сессией

1. Запусти новую **маленькую** одиночную карту с небольшим количеством юнитов; убедись, что есть `OVDIAG CONFIG`.
2. Поставь 1–2 конных вне построения, затем настоящий отряд тяжёлой конницы; проведи их к мушкетёрам, отдельно к пикинёрам. Дай коннице время набрать скорость.
3. Проверь двух вражеских кораблей и одну пушку с гаубицей. Проверь HP башни, стены, отсутствие мортиры в артдепо и мортирного выстрела у галеры.
4. Тест ИИ с лимитом 10 — отдельный долгий сценарий, не смешивать с боевым тестом.
5. Присылай новый `cos_*.log`. Можно сразу построить отчёт:

```bash
python tools/analyze_overhaul_log.py "/путь/к/cos_новый.log" -o overhaul_report.txt
```

Предыдущий лог `cos_261028_174754.log` был сформирован **без** новых OVDIAG-маркеров; смотреть надо новый, после установки диагностического генератора.

## Меры безопасности

Не запускать `Full` в массовой битве: десятки тысяч попаданий создадут огромный лог, высокий расход CPU/диска и могут испортить FPS. Для массовой игры собирай вариант `Compact` или откатывайся на обычный генератор фазы 1. Пока PowerShell и игровой Pascal-подобный скриптовый код не были выполнены на Windows/в игровом движке: возможна ошибка компиляции, и в этом случае нужен новый лог.
