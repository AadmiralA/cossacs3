# Gameplay Overhaul / этап 1 (эксперимент, НЕ ТЕСТИРОВАН В ИГРЕ)

Ветка: feature/gameplay-overhaul-phase1 (основана на working naval acceleration/ramming v7).
Генератор: tools/build_gameplay_overhaul_phase1.ps1.
Исходные файлы reference/ никогда не изменяются; генератор сохраняет новые override-файлы только в mod/data/.

## Реализовано в генераторе (требует проверки движком)

1. **Конница:** постепенный разгон с 35% до 100% штатного MoveStep: легкая за 4, тяжелая за 6 единиц игрового времени. Применяется к классам hardhorse, fasthorse, horseshooter.
2. **Тяжелая конница:** при движении в настоящем сформированном отряде (squad exists, fFormation>=0), в направлении вражеской пехоты, разгоняет *временный* множитель перемещения с 1.0 до 2.5 в течение около 3 единиц игрового времени, затем плавно возвращает к 1.0; вне натиска базовая максимальная скорость неизменна.
3. **Экспериментальный натиск:** только конница в настоящем построении; поиск вражеского наземного юнита впереди, удар через штатную _misc_DoDamage при контакте (расстояние по радиусам), 5 единиц игрового времени между ударами одной конной единицы. Удар по бойцу без настоящего построения рассчитан как гарантированно смертельный **базовым уроном 500000 до глобального штрафа/защиты** (реальную смертность проверить). Сформированным отрядам — 250 базового урона до штрафов.
4. **Пикинёры:** при определении класса lightinfantry с оружием pike натиск по такому юниту не наносит специального урона, ускорение к такой цели не активируется. Полноценное групповое блокирование копьями на всей ширине фронта ещё не создано.
5. **Урон мобильных юнитов:** множитель 0.625 (= /1.6) внутри _misc_DoDamage. Работает для ударов с корректным атакующим; не меняет бесхозные взрывы, урон зданий и исцеление.
6. **Без построения:** ещё 0.65 к урону, плюс пауза между атаками увеличивается в 1/0.65 для оружия с положительной базовой паузой. Реальное построение проверяется по TSquad.fFormation>=0, а не только наличию squad.
7. **Артиллерия:** cannon/howitzer ходят с MoveStep 0.018 вместо наследуемого 0.03 (на 40% медленнее). Начальная пауза cannon/howitzer/mortar/supermortar умножена на 1.5. Повторное изменение паузы апгрейдами требует отдельного исследования.
8. **Артиллерия ИИ:** нормальный экономический план считает cannon/howitzer/mortar/mbarrel вместе в лимите 10, не заказывает минометы; дополнительный серверный запрос производства _player_CheckAccessControlRequirements запрещает боту новые единицы артиллерии при существующем суммарном количестве >=10 по нативным artcount[].
9. **Мортиры:** удалены из списка членов страны и доступного производства артдепо. Оригинальные игровые ресурсы физически не удаляются и старые сохранения не переводятся.
10. **Галера:** отключён второй (мортирный) слот оружия.
11. **Каменные стены:** HP ×2. Деревянные стены: HP ×1.5. Каменные башни (usage tower): HP ×3.
12. **Корабли:** работающие механики NavalRamming v7 сохраняются; урон корабельного тарана теперь тоже может попадать под общий множитель снижения мобильного урона (контроль на тесте).

## НЕ реализовано; дальнейшие этапы

- Физическое прохождение 3 рядов мушкетёров и блокировка натиска фронтом пикинёров как единой геометрией (требуются правила коллизий, направления, раздвигания юнитов).
- Два прикрепленных человека как обязательный расчёт для передвижения и стрельбы пушек/гаубиц.
- Устранение разворотов «полукругом» при начале движения пушек и кораблей, физическая инерция при торможении; нужен анализ путей, поворотной кинематики.
- Истощение источников камня с исчерпаемым остатком и синхронизацией с добычей.
- Новая модель потребления золота ровно каждые 60 секунд, сохранение прежних дорогих юнитов, добавление малой платы остальным.
- Массовые переходы юнитов к врагу без золота, в том числе особая 25% вероятность для отрядов. Определить, какой именно игрок/фракция получает мятежников; не допускать десинхронизации.
- Ускоренная смерть при голоде вдвое.
- Отступление отряда при 85% потерь с проверкой помощи (радиус егеря ×1.4; союзные отряды ×3), поиском ближайшего центра или резервного отряда, временной блокировкой управления, сохранением статистики исходной численности.
- Новая крепость по примеру AoE 2 (потребуется новая модель/иконка/привязка к строительству).
- Восемь отдельных орудий на башне по уровням улучшений (требует изменения механики выстрелов, ресурсов/позиции и апгрейдов, а не только паузы).
- Точные ограничения производства уже заказанных, но не выпущенных пушек при лимите 10 (очередь должна учитываться дополнительно).

## Как собрать

В Git Bash, из папки D:/Work/Cossacs3-mod/cossacs3:

    git fetch origin
    git switch feature/gameplay-overhaul-phase1
    git pull --ff-only origin feature/gameplay-overhaul-phase1
    powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./tools/build_gameplay_overhaul_phase1.ps1

Скопировать следующие ВОСЕМЬ файлов из mod/data/ по тем же относительным путям в Cossacks 3/mods/NavalRamming/data/:

    scripts/dmscript.global
    scripts/units/unit.inc/initial.inc
    scripts/units/unit.inc/nothing.inc
    scripts/units/global.inc/progresseconomicai.inc
    scripts/lib/unit.script
    scripts/lib/miscext2.script
    scripts/lib/country.script
    scripts/lib/player.script

**Внимание:** новая структура TObj (ещё 4 поля cavalry*) отличается от v7. Не загружать старые сохранения, не использовать онлайн или replay. Перед заменой сделать резервную копию текущей папки NavalRamming. Отключить другие игровые моды.

## Как тестировать, по порядку

1. Запуск на новой офлайн-карте: отсутствие ошибок загрузки / компиляции / критических исключений.
2. Корабли: 2 вражеские галеры, не потерялся HIT; фрегат/линейный корабль разгоняются.
3. Стены и каменная башня: сравнить HP с базовой игрой (×2/×3).
4. Галера: второй мортирный выстрел недоступен; артдепо не производит мортиры.
5. Пушка/гаубица: ходят медленнее; пауза между выстрелами больше.
6. 2 конных юнита вне построения: обычный разгон есть, но специального удара нет.
7. Сформированный отряд конницы против одного врага без отряда: обнаружение CavalryCharge HIT, проверить HP цели.
8. Отряд тяжёлой конницы рядом с пехотой без пик: бонус скорости должен постепенно увеличиваться; проверь возможность управления и анимацию.
9. Отряд конницы против пикинёров: не должно быть CavalryCharge HIT по пикинёрам.
10. ИИ: построить артдепо, дождаться артиллерии, проверить суммарный лимит в 10.

Собираем первую диагностику после каждого шага; НЕ следует тестировать все механики одновременно.

**Результаты проверки:** в GitHub сверены места вставки, но PowerShell скрипт и Pascal-подобный игровой код НЕ были выполнены/скомпилированы вне игры. Возможны ошибки движка и исправления в следующем коммите.
