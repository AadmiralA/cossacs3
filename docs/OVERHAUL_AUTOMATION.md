# Автоматизация разработки Cossacks 3 / Gameplay Overhaul

Основная проблема: запуск игры занимает ~63 секунды только на этапе \`LoadFromStreamProject\` (лог \`cos_261028_184328.log\`). Повторный ручной ввод восьми путей к файлам не должен требоваться вообще.

## Один раз: путь к установленной игре

В **Git Bash** из корня проекта:

~~~bash
cd /d/Work/Cossacs3-mod/cossacs3
git switch feature/gameplay-overhaul-phase1
git pull --ff-only origin feature/gameplay-overhaul-phase1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./tools/overhaul_oneclick.ps1 -GameRoot "D:\SteamLibrary\steamapps\common\Cossacks 3" -Update
~~~

**Замени** пример пути \`D:\SteamLibrary\steamapps\common\Cossacks 3\` на фактическую папку, где находятся \`cossacks.exe\` и \`editor.exe\`. После первого запуска путь сохраняется *только локально* в \`%LOCALAPPDATA%\Cossacks3Overhaul\game-root.txt\`; он **не записывается в GitHub**.

Папка \`mods\NavalRamming\data\` должна уже существовать, а сам мод должен быть включён в менеджере игры. Игровые оригиналы \`data/\` и репозиторные \`reference/\` не переписываются. Никаких старых сохранений и мультиплеера для экспериментальных полей данных!

## Самый простой вариант — двойной щелчок

После первой настройки можно просто открывать **`tools/TEST_MOD.cmd`** для обновления, установки и запуска игры с автоматическим сбором лога. Если нужно проверить сборку **без открытия игры**, запусти **`tools/CHECK_MOD.cmd`**. Окно консоли останется открытым для ошибок и результата.

## В дальнейшем: одна команда на тест

~~~bash
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./tools/overhaul_oneclick.ps1 -Update
~~~

Что делает скрипт:

1. Без принудительного сброса Git обновляет ветку \`feature/gameplay-overhaul-phase1\` через \`git pull --ff-only\`; при конфликте останавливается.
2. Пересоздаёт восемь игровых файлов генератором \`build_gameplay_overhaul_diagnostics.ps1\` (по умолчанию \`Compact\`, в крупном бою не переполняет лог HP-событиями).
3. Проверяет наличие всех восьми файлов, их размер, ключевые изменения (\`0.006\` для артиллерии, оба режима перезарядки, штраф после брони, запись HP).
4. Создаёт резервные копии **существовавших** восьми override-файлов в \`%LOCALAPPDATA%\Cossacks3Overhaul\runs\<timestamp>\backup\`.
5. Копирует их в \`mods\NavalRamming\data\`, сверяет SHA-256 и при ошибке копирования пытается откатить предыдущие файлы.
6. Открывает Steam-игру по штатному ID **333420**; процесс \`cossacks.exe\` остаётся под наблюдением. Игра загружается столько же, сколько и раньше.
7. Когда игра закрыта и лог найден, копирует свежий \`cos_*.log\` в папку запуска, создаёт \`summary.txt\` и, если установлен Python, \`overhaul_report.txt\` с нашим анализатором.
8. Выводит в терминал три пути. Для совместной отладки можно присылать \`overhaul_report.txt\` и исходный \`cos_*.log\`.

**Терминал во время игрового теста должен оставаться открытым**. Скрипт не нажимает на кнопки игры и не создаёт тестовую карту: механики, связанные с движком, по-прежнему требуют действий человека. Если Steam не запустит процесс за 180 секунд или окно PowerShell было закрыто, сбор лога можно выполнить отдельно.

## Без запуска игры — для большей части небольших изменений

~~~bash
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./tools/overhaul_oneclick.ps1 -Update -NoLaunch
~~~

Сборка и статические проверки выполняются без повторного запуска. **Это не полноценная компиляция игровым движком**, поэтому новые Pascal-символы/состояния и физику столкновений таким способом гарантировать нельзя.

## Один запуск редактора и много тестов

~~~bash
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./tools/overhaul_oneclick.ps1 -Update -Editor
~~~

Открывает \`editor.exe\`, в котором доступно переключение теста/редактора через \`Ctrl+T\`. Полезно один раз подготовить **свою небольшую карту** с двумя сторонами, мушкетёрами в построении и без, эскадроном тяжёлой конницы, одной пушкой и одной башней. На одной открытой карте можно быстро повторять разные сценарии. Изменения исходников во время уже запущенного редактора не гарантируют горячую перезагрузку — после новой сборки обычно нужен новый запуск процесса.

## Отдельно собрать последний лог

~~~bash
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./tools/overhaul_oneclick.ps1 -CollectOnly
~~~

Ищет \`cos_*.log\` в \`<GameRoot>\log\` и запасных \`Documents\cossacks\log\`. Для автоматически создаваемого лога рекомендуются настройки в \`cossacks.ini\`:

~~~text
LogFileEnabled = true
LogFileRoot = true
~~~

В \`Full\` логируется каждое попадание и каждый расчёт атаки; для больших схваток используй только \`Compact\`. Один тест на один набор исправлений — лучше, чем много раз запускать игру для единичных правок.

## Что всё ещё нельзя автоматизировать без дополнительных функций движка

- Настоящая симуляция физики кораблей/конницы, столкновений, построений, анимаций без запуска игры.
- Автоматическое создание игровых отрядов и их перемещение через этот PowerShell-скрипт.
- Проверка работоспособности игровых Pascal-скриптов независимым компилятором: пока у нас нет движкового компилятора в инструментарии.

## Что делать, если что-то пошло не так

- Если не найден путь: передать \`-GameRoot "...\Cossacks 3"\` повторно.
- Если не найдена папка мода: создать/включить \`NavalRamming\` в менеджере модов.
- Если \`git pull --ff-only\` не проходит: не удалять свои изменения, отдельно проверить \`git status\`.
- Если новая сборка ломает запуск: восстановить отдельные файлы из \`backup\` последнего каталога запуска.
- Если нет лога: проверить \`cossacks.ini\` и поискать его в \`<GameRoot>\log\`.
- Если Git Bash закрыт до выхода игры: повторить с \`-CollectOnly\`.

Скрипт подготовлен и проверен на уровне исходного текста; **реальный запуск под Windows PowerShell и внутри Cossacks 3 ещё не подтверждён**. При первой ошибке сообщи текст ошибки консоли.
## Автопроверки на GitHub

В ветку добавлены `.github/workflows/overhaul-offline.yml` и `tools/test_overhaul_offline.py`. При изменениях генераторов или исходных reference-файлов GitHub Actions должен запустить Windows-генератор и проверить результат Python-тестами. Открыть вкладку [Actions](https://github.com/AadmiralA/cossacs3/actions) и посмотреть результат workflow **Gameplay Overhaul offline checks**. Это позволяет обнаруживать ошибки сборки до запуска игры, но не заменяет проверку физики в движке. Первый запуск этого workflow в PR завершился успешно: генератор и Python smoke-тесты прошли на Windows (<https://github.com/AadmiralA/cossacs3/actions/runs/40720628266>). Это **не означает**, что сама игра с новыми скриптами прошла тест. Позже workflow может не запускаться, если Actions отключены настройками репозитория; бесплатные минуты также зависят от условий GitHub.

Локальный аналог тестов после генерации:

~~~bash
python -m unittest discover -s tools -p test_overhaul_offline.py -v
~~~
